# 0.20.0 account integrity review fixes

Baseline: `feature/v0.20.0-accounts-sync`, commit `3c9974c87fb1cf4aca2976f7af7fb8e2fbbc0c69`.

## Behavior and scope

An account recovery GET could previously replace a backup imported while the request was waiting, or erase a draft written by another tab after recovery started. Imports are now disabled at the Settings entry point and confirmation dialog during account operations. The account controller independently rejects overlapping imports. A remote replacement checks the local edit version, external change version and persisted cache checkpoint before writing. A changed checkpoint cancels replacement and keeps the draft/recovery warning; a subsequent explicit confirmation is required.

The same cache checkpoint check protects autosave, import and upload preparation when a storage event has not yet arrived. Storage clear events are also detected. These checks preserve the current snapshot and the changed shared cache rather than silently replacing either. Existing recovery keys and backup/export controls remain in use.

The API now treats null optional reminder fields as omitted and always includes a section's root `parentId`. This applies when validating new input and serializing an older stored snapshot; merely reading a notebook does not rewrite database records. Required fields retain their validation. No schema migration is needed.

The frontend prepares an outbound snapshot copy with counter timestamps converted to ISO UTC. This allows valid legacy/imported dates to pass the API's timestamp contract without mutating the guest notebook or backup. Counter dates outside years 0001–9999 fail locally with a specific correction message. Snapshot equality accounts for equivalent counter instants and object key order so a successful normalized upload does not remain falsely marked as pending. Actual content edits remain dirty.

No dependency packages, notebook schema versions or storage keys were added. No CSS redesign or password-policy change is included. Browser draft isolation is not encryption; automatic background synchronization remains a separate delivery.

## Regression coverage

- Controller: overlapping import rejection, import retry after completion, local edits during recovery, external writes with and without delivery of a storage event, explicit recovery after cancellation, autosave/upload preservation and canonical date acknowledgement.
- Shared JSON fixtures: API POST/GET/PUT responses match frontend-readable canonical snapshots; legacy counter input normalizes without mutation; both create and update send canonical copies.
- Backend: existing nullable snapshots can be loaded without database rewrites.
- Browser, desktop and mobile: a file selection already in flight cannot confirm replacement during recovery; a later import survives reload/login; a real second tab's durable draft survives its closure and the first tab's delayed response, and remains exportable before explicit recovery.
- Real API integration: guest data contains a legacy counter timestamp, account creation/upload and subsequent revision-checked sync succeed, the guest snapshot remains unchanged and reauthentication reads the stored account notebook.

## Apply and validate on Windows

Use the existing 0.20 feature branch with the baseline changes already committed. Put the incremental patch in the repository root, check the working tree, then apply:

```powershell
git status --short
git branch --show-current
git apply --check .\tomohu-v0.20.0-review-fixes-3c9974c.patch
git apply .\tomohu-v0.20.0-review-fixes-3c9974c.patch
```

Run frontend checks from the root:

```powershell
npm.cmd run lint
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd run typecheck
npm.cmd run test:e2e
```

Keep PostgreSQL running in Docker. Stop the ordinary development API before the separate live integration runner, which needs port 8000. From the root, validate the backend and then the live flow against the dedicated test database:

```powershell
Push-Location backend
try {
    .\.venv\Scripts\python.exe -m ruff check .
    .\.venv\Scripts\python.exe -m ruff format --check .
    $env:TOMOHU_TEST_DATABASE_URL = 'postgresql+psycopg://tomohu:tomohu@localhost:5432/tomohu_test'
    .\.venv\Scripts\python.exe -m pytest
} finally {
    Remove-Item Env:TOMOHU_TEST_DATABASE_URL -ErrorAction SilentlyContinue
    Pop-Location
}
$env:TOMOHU_E2E_DATABASE_URL = 'postgresql+psycopg://tomohu:tomohu@localhost:5432/tomohu_test'
try {
    .\backend\.venv\Scripts\python.exe scripts\run_live_e2e.py
} finally {
    Remove-Item Env:TOMOHU_E2E_DATABASE_URL -ErrorAction SilentlyContinue
}
git --no-pager diff --check
```

Review each command's result: PowerShell does not necessarily stop after a failed native command. Expected totals are shown above. Do not include temporary `.patch` files in the commit. Check the new CI run before merging.

## Recovery

Export open/preserved snapshots before resolving a cross-tab warning or intentionally replacing a notebook. A cancelled GET can be retried after the user reviews the draft and confirms again. No implicit upload or merge is introduced. Revert this focused commit if needed; preserve account caches and exports before reverting. Guest backups retain their original date strings, schema and storage key.
