# 0.22.1: Privacy review fixes

Baseline: main commit `084896de1ba77c58ea5c01b17651e5d269ebb574`, after the v0.22.0 merge. Working branch: `fix/v0.22.1-privacy-review`.

## Corrected behavior

1. Dialog inputs, submit buttons, close/Escape actions and bottom navigation are blocked while the related account/privacy operation is pending. A second form edit cannot be discarded by an older public restoration. Private mutation handlers also reject changes during the operation.
2. A successful restore immediately applies the returned public notebook and removes the stale private card. Metadata refresh runs separately: a later network failure cannot prevent the committed result from reaching the UI/cache.
3. Failed private listing retains the last successful list and reports the failure explicitly. The retry action works without a page reload. Requests from an earlier account/workspace cannot replace the current list.
4. Empty or whitespace-only content settings titles use `Sem título`, consistently with the normal content editor, before any save request.
5. Private import is disabled with guidance to return to the common notebook. A selected file cannot bypass this restriction. Public/guest backup import remains available.

The metadata state is separated into `usePrivateItems`; the old silent empty-list fallback was removed. No packages, environment keys, migrations or saved-data format changes are needed. Existing public/private snapshots and account/privacy passwords remain unchanged. The backend version is updated for consistency with the patch release.

## Manual regression check

- Remove privacy and confirm the form cannot be edited or dismissed until the operation finishes. Previously submitted changes must remain present afterward.
- In content settings, save an empty title. It must become `Sem título` and save normally.
- Inside a private item, Settings must explain why import is unavailable. Return to the common notebook and confirm import is available again.
- Verify account login, opening private cards, autosaving, returning to the common notebook and privacy-password recovery normally.

Network failures, delayed restore responses and stale metadata responses are covered by the automated regressions; no development-database interruption is needed to simulate them manually.

## Private draft follow-up

This complementary fix applies after the original 0.22.1 review patch.

- Private autosave defers a temporarily blank inline content title. Typing a valid replacement resumes the normal debounce; leaving the field keeps the existing `Sem título` fallback. Explicit flush reports incomplete input without pausing future automatic saves. Network and revision conflicts still require explicit recovery.
- A dirty private draft blocks opening, creating or copying another notebook and logging out even after privacy access expires. The account panel explains how to save or export and explicitly discard the draft.
- Expired account sessions can authenticate again with the same account while preserving the private draft. Switching credentials to another account or registering a new account stays blocked until that draft is resolved.
- No database migration, environment change, dependency or stored-format change is required.

Regression coverage includes desktop/mobile inline-title recovery, privacy expiry, account expiry, rejected account switching and unlocking the retained draft after reauthentication. Repeat the frontend checks and the real account/privacy runners above before committing on Windows.

Follow-up validation: frontend lint, formatting, build, type checks, 79 unit tests and 38 component tests passed; the full browser suite passed 118 tests with six live cases skipped. Separate real-API runners passed all four account and two privacy cases. PostgreSQL passed all 129 backend tests.
