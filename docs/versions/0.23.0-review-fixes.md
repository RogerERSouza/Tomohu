# 0.23.0 review recovery fixes

Baseline: `593937056cca5249a482b98165267e35e17297e6` on the account-access branch. Apply this follow-up to that branch, not to the older main baseline. No database migration or dependency update is needed.

## Behavior and implementation

- Keep the common notebook controller mounted across authentication rejection, rendering only the authentication screen until the session is restored. The draft remains in memory without displaying account content before login. Reauthentication into the same workspace resumes that controller.
- An unsaved draft whose browser cache cannot be written requires the same account for recovery. After authentication, save or export before switching workspace/logging out. A before-unload warning explains the risk of closing or reloading; memory cannot survive closing the page when every durable write fails.
- A failed cookie logout plus expired bearer no longer suppresses the unconfirmed remote-session warning. Explicit local sign-out remains enforced independently.
- Legacy read failures retain the last successfully read bytes, show the error and offer retry. Export falls back to that retained copy with explanatory UI text. Copying requires a successful current read and fresh confirmation when the source changed.
- Remove the unreachable signed-out status from the authenticated notebook view. Keep the existing layout and notebook formats.

See acceptance criteria AC11–AC13 in [the account-access specification](../specs/mandatory-accounts.md).

## Local verification

Run the standard frontend checks, TypeScript and the full browser suite. Run backend pytest/Ruff and both live browser suites with the dedicated test database. The backend regression establishes that a bearer `401` can coexist with a usable browser renewal credential, so it cannot be treated as proof of revocation.


Use the existing [0.23 validation guide](0.23.0.md) for PostgreSQL/backend/live-suite commands. Stop manual API/frontend servers before the live runners.

## Manual checks

1. With a synthetic account, edit a common note and verify normal reload/synchronization still works.
2. Exercise session-expiry recovery with blocked browser storage through the automated regression; after authentication, the unsaved text must remain and another-account login must be blocked until recovery.
3. Verify local logout closes account content even when remote logout fails; the warning must remain visible.
4. Exercise legacy read failure/retry and verify the exported last-read JSON remains intact.

Do not clear browser storage or close a tab with an unpreserved draft. Do not use production accounts or databases as test fixtures.

## Executed evidence

- ESLint, Prettier, TypeScript and production build passed.
- 79 unit tests and 32 component tests passed.
- 130 desktop/mobile browser tests passed. Six live-API cases were skipped by that command and passed separately: four account cases and two privacy cases, with PostgreSQL and the mail worker.
- 139 backend tests passed with PostgreSQL; Ruff check and format check passed. The pre-existing TestClient/httpx deprecation warning remains.
- AC11: `accounts.spec.ts` verifies blocked browser writes, authentication rejection, protected content hidden, the unload warning, rejection of another-account login, recovery into the same notebook, and later synchronization of the original unsaved text.
- AC12: `accountReviewFixes.spec.ts` verifies the unconfirmed-logout warning; `test_browser_logout_contract.py` verifies that an expired bearer logout does not revoke a usable renewal session.
- AC13: `legacyReadFailure.test.tsx` retains the actionable error; `accounts.spec.ts` verifies byte-preserving export during read failure, retry, fresh consent and subsequent account copy.
- The password-reset layout test now reads both control rectangles in the same animation frame, preserving the existing spacing assertion without timing-dependent geometry.
- Patch application was verified against a clean `5939370` checkout and changed file bytes were compared.

The fix preserves drafts only while the page remains open if durable storage is unavailable. It cannot recover memory after a forced reload, browser crash or closing the tab; export/save before leaving. Production TLS/proxy and Windows-specific behavior still require local operational checks.
