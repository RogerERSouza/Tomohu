# Tomohu 0.21.0 — Account lifecycle

Baseline: main `fcea770839f6af7d71a5c3694e31497935d4f0d8`.
Branch: `feature/v0.21.0-account-lifecycle`.

## Scope and compatibility

- Request password recovery with a generic response, then confirm a single-use email link within 30 minutes. Choose the new password twice; no automatic login follows recovery.
- Confirm email explicitly and inspect/resend confirmation in **Segurança da conta**.
- Change a password using the current password. List active sessions, revoke another session, the current session, or all sessions.
- Password reset/change revokes all database sessions. Logout revokes the current bearer token, including copied tokens. Existing credentials, notebooks, ownership, revisions, local guest data and account recovery caches are preserved.
- New passwords follow the requested 5–128 character policy with an ASCII uppercase letter, lowercase letter and digit. Old passwords still work at login.
- Access tokens remain memory-only, expire in 15 minutes by default, and require login after reload. Email verification is displayed; it does not newly block existing notebook access. Refresh tokens, OAuth, automatic sync and public hosting are outside this release.

See [ADR 0004](../architecture/0004-account-lifecycle.md) for the security design.

## Apply on Windows

Start with a clean, updated main. Keep the patch outside commits.

```powershell
git status --short
git switch main
git pull --ff-only
git switch -c feature/v0.21.0-account-lifecycle
git apply --check .\tomohu-v0.21.0-account-lifecycle-fcea770.patch
git apply .\tomohu-v0.21.0-account-lifecycle-fcea770.patch
npm.cmd ci
```

If the branch already exists, use `git switch feature/v0.21.0-account-lifecycle`
instead of creating it again. If `git apply --check` fails, stop before applying;
compare the baseline and local changes first.

## Configure local mail and migrate

Open Docker Desktop first. In `backend/.env`, keep the current database settings.
Set these additional values:

```dotenv
TOMOHU_FRONTEND_URL=http://localhost:5173/
TOMOHU_MAIL_MODE=outbox
```

If your frontend uses another port or base path, use its actual URL. A deployed
GitHub Pages frontend needs its complete `/Tomohu/` base path. The origin also
needs to be in `TOMOHU_CORS_ORIGINS`.

Generate a secret once:

```powershell
.\backend\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

Copy the generated value into `TOMOHU_JWT_SECRET` in `backend/.env`. Keep an
existing random secret if one is already configured. Never commit `.env`. API and
mail worker must use the SAME secret and database. Restart both after changing it.
An empty secret works for basic development login but cannot deliver valid mail
across separate processes; the worker explicitly rejects it.

Apply the migration before starting the API:

```powershell
cd backend
docker compose up -d
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

In a second terminal at the repository root, run the mail worker:

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.email_worker
```

Keep both terminals running. For one delivery batch instead of a continuous
worker, append `--once`. Local email is saved in `backend/.outbox/*.eml`; it is NOT
sent to a real inbox. Open a file as text and copy its complete frontend link into
the browser. The latest requested link replaces older links of the same purpose.
Those files contain secrets: do not publish or commit them.

Start the frontend in a third terminal, with its existing `.env.local` setting
`VITE_API_BASE_URL=http://127.0.0.1:8000`, using `npm.cmd run dev`.

## Manual checks

1. Export a backup before testing account operations. Register a new account with the new password policy. Open the queued verification link; opening alone must not verify. Confirm explicitly and refresh verification status in the account panel.
2. Request recovery while logged out. An unknown address receives the same UI response. Deliver queued mail, choose a new password twice, and confirm. Old credentials and old sessions must stop working; notebook content must remain unchanged.
3. Request a newer link and try the older one. Reuse a consumed link and try an expired link. Each must fail without changing data.
4. Open a notebook and edit without syncing. Change the password. The local draft remains open and exportable while the session is ended. Reauthenticate as the same account and confirm the draft remains; synchronize explicitly.
5. Sign in from another browser context. Revoke that session from the first context; its next API request must fail. Revocation cannot erase data already downloaded onto another device.
6. Check security controls at 360 px width in both themes. Home, section cards, note editing and reminder controls retain their existing appearance.

The existing FastAPI/Starlette `httpx` deprecation warning remains; tests pass.
Native Windows execution and remote CI must be repeated after applying and pushing
this patch. Local checks do not guarantee an absence of all bugs.

Real SMTP transport is tested with a controlled transport double, not by sending
mail to a real provider. Configure a verified sender and authenticated STARTTLS
SMTP (normally port 587) before production. Run the worker as a supervised process
and monitor failed/expired queue records. A crash after SMTP acceptance can resend
the same link; consuming it remains single-use. Expired session and token records
remain available for operational inspection; configure database retention before
public deployment. Shared rate limiting across multiple API workers and production
hosting are still separate operational work.

Migration 03 is additive. Previous access tokens must log in again after upgrade.
Downgrade refuses to discard lifecycle records. Do not delete accounts, notebooks
or queue records merely to force a downgrade; restore from a reviewed backup or
prepare an explicit migration instead.
