# Tomohu 0.19.0 — Snapshot and interval validation corrections

Date: 2026-11-09. Patch baseline: `944a72523da3247c4b8d02f4b11560ee0caeabfa` on `refactor/v0.19.0-frontend`.

## Scope and behavior

This correction completes the snapshot validation findings from the second branch audit. It remains part of the unmerged 0.19 frontend release. Backend source, dependencies, schema version 1, browser keys, hash routes and styles are unchanged.

| Reproduced defect                                                                                | Corrected behavior                                                                                                                                  |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| An invalid imported reminder date crashed calendar editing                                       | Reject invalid calendar dates and clock values at the data boundary; a calendar receiving an invalid value can still render and select a valid date |
| Duplicate section IDs caused combined deletion; missing references produced inaccessible content | Require nonempty, unique IDs within each collection, existing parent/content references and an acyclic section hierarchy                            |
| A multi-day selection with equal dates accepted an inverted continuous interval                  | Use one pure start/end comparison in both snapshot validation and the form; valid overnight intervals remain accepted                               |
| Negative or overflowing imported counter totals were accepted                                    | Require finite, nonnegative totals; preserve legitimate negative correction entries and reject nonfinite mutation inputs/results                    |

List item IDs are unique within each list; counter entry IDs are unique within each counter. IDs may be reused across independent lists or top-level entity types, preserving existing scoped identity behavior.

## Boundaries and cleanup

- `lib/notebookValidation.ts` owns snapshot shape and integrity validation. `lib/notebook.ts` retains its public `isNotebook` export and backup parser, while the previous inline implementation is removed.
- `lib/time.ts` supplies pure calendar/clock predicates. `lib/reminders.ts` shares interval rules between validation and feature UI.
- Domain validation imports only domain types and helpers, never React, feature state, pages or browser storage. There is no circular import between notebook operations and validation.
- Remove obsolete numeric checks in local date construction after delegating validation to the shared predicates. No dependency packages, unused compatibility implementations, or broad architectural changes are added.

## Data compatibility and recovery

Valid legacy ISO reminder dates, date-only reminders, leap days, scheduled reminders, correction history and existing keys remain supported. Backups are validated without mutation; invalid data is not silently repaired or partially imported.

An inconsistent backup is rejected before replacement confirmation and leaves current browser data intact. If inconsistent data is already in browser storage, the existing preservation flow keeps its original bytes and pauses autosave. A valid explicitly confirmed replacement resumes saving. This patch does not automatically erase or repair existing inconsistent records; retain their original backup when preparing a valid replacement.

Two older timestamp/schema test fixtures contained orphan content even though their purpose was testing timestamps or shape validation. Their sections now include the referenced parent; assertions and validation requirements are retained.

## Apply and validate on Windows

Run from the repository root, on `refactor/v0.19.0-frontend`, after saving a browser backup. Confirm a clean working tree and the expected baseline before applying. The patch is incremental over `944a725`; do not apply it to main or reapply earlier patches.

```powershell
git status --short
git rev-parse --short HEAD
git apply --check .\tomohu-v0.19.0-validation-fixes-944a725.patch
git apply .\tomohu-v0.19.0-validation-fixes-944a725.patch
npm.cmd run lint
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd run typecheck
npm.cmd run test:e2e
git --no-pager diff --check
```

`git apply --check` verifies applicability without changing files. The second command applies the source, regression tests and this record. The npm commands validate the result. Keep the downloaded `.patch` out of the commit. No database migration or Docker command is needed for this frontend correction.

If the commit or working tree differs, stop before applying and inspect the difference. After application, manually confirm invalid-import rejection preserves a current note and that a valid overnight reminder saves, reloads and can be removed.
