# Tomohu 0.18.0 — Backend authentication and ownership

This release replaces the incomplete experimental local API integration with the agreed authentication milestone. The frontend uses the stable 0.17 behavior and keeps its current storage format. No active notebook is uploaded or replaced.

## Changes

- Register, login, and current-user API contracts.
- Case-insensitive email identifiers with database uniqueness.
- Argon2id password hashing, bounded password length, short-lived signed JWTs with strict claim validation.
- Shared request transaction and authenticated owner lookup for every notebook endpoint.
- Account disabling, per-process abuse limits, no-store API responses, and redacted validation errors.
- Additive migration with FK/index and preservation of unowned legacy snapshots.
- Automated authentication, isolation, concurrency, migration and configuration regression tests, plus PostgreSQL CI.
- Documented architecture and subsequent release boundaries: 0.19 frontend refactor; later authenticated integration.

## Deliberate limits

This is a backend milestone. There is no login screen, automatic synchronization, migration of browser data, refresh token, logout revocation, recovery email or verified-email workflow. Native PostgreSQL release tests have passed locally; public production deployment still requires operational review and the account lifecycle features described in the ADR. See the backend guide and ADR for safe upgrade and recovery.

The delivery report records the exact commands and environments actually executed. The CI definition is a reproducible check, not evidence of a completed remote run. No production deployment or main merge is performed by this patch.

- Frontend lint, Prettier check, 17 regression tests and production build passed.
- Backend Ruff check, Ruff format check and 56 tests passed using isolated SQLite databases, with migrations rather than create_all.
- Real HTTP smoke against Uvicorn passed for registration, login, owner-scoped creation/read/update, 401/404/409 behavior, and OpenAPI docs.
- Alembic emitted the PostgreSQL upgrade SQL successfully.
- Two focused checks (legacy migration/schema agreement and cross-account access) passed on PGlite's PostgreSQL WASM engine. PGlite did not reproduce the full integration environment: startup search_path options were not honored, and a multi-connection concurrency check timed out. These results are not native PostgreSQL verification.
- A standard native PostgreSQL server could not run in the implementation environment. This original verification gap was closed by the local PostgreSQL 17 checks reported below. The CI workflow has been added; no completed remote CI run is claimed here.
- No frontend browser regression run was performed: src/ and frontend tests are identical to stable main. The experimental development-only API control is removed when applying over the earlier branch. Comprehensive browser regression coverage belongs to 0.19 before structural changes.
