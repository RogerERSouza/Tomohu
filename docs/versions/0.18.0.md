# Tomohu 0.18.0 — API client (development-only)

Introduces a typed HTTP adapter for the existing notebook snapshot API. The adapter is deliberately not wired to automatic persistence or the UI: remote notebook IDs are not authentication and must never be exposed as a public sync feature. Local browser storage remains authoritative. A subsequent authenticated workflow can explicitly opt in to migration after backups and conflict resolution exist.

- Only `http://localhost` and `http://127.0.0.1` are accepted as API origins.
- Requests omit cookies and disable caching.
- API responses are validated before use.
- HTTP 409 is reported as a conflict rather than retried blindly.
- No notebook IDs, tokens or credentials are persisted.

Technologies: native Fetch API, TypeScript, FastAPI snapshot contract, PostgreSQL. No new dependency.

## Validation and safe integration boundary

- Added HTTP client tests for origin restrictions, request shape, successful responses,
  revision conflicts, malformed responses and offline errors.
- Redirects are rejected to avoid forwarding notebook snapshots to another origin.
- A remote snapshot is never loaded into or written over `localStorage` by this module.
- **Not a production synchronization feature:** authentication, ownership checks,
  verified backups, recovery and a conflict-resolution UX are prerequisites.
