# Tomohu 0.21.0 — Account review fixes

Baseline: `0a5e972d71c52a68b2f9fb8af463fccd42e022b8` on
`feature/v0.21.0-account-lifecycle`.

## Changes

- Confirm email links against the current signing key before their atomic, single-use consumption. Rotating the key rejects previously issued links, including delivered mail. Newly requested links continue to work. Token contents remain hashed at rest and malformed non-ASCII secrets return a controlled error.
- Complete local logout after a failed remote revocation attempt, retaining guest data and account drafts. A visible message explains that the server could not confirm revocation and the remote session may remain valid until expiry. An HTTP 401 means the token is already invalid. Existing export requirements remain in force before switching workspaces.
- Refresh the account user in the central controller so verification stays correct after closing and reopening Settings. Expired refresh requests preserve the open draft and require login again.

Keep the existing `.env`, signing key and database. This correction changes no saved notebook format and requires no database migration.

## Manual confirmation

1. With a pending account edit, interrupt API access and choose **Sair e voltar ao caderno local**. The guest notebook opens and a warning distinguishes local logout from unconfirmed server revocation. Restore access, log in and reopen the account notebook; the draft must remain.
2. Confirm email, use **Atualizar confirmação**, close Settings and reopen it. The status must stay verified.
3. Use a dedicated test account/environment for key rotation: deliver a link, change the signing key, restart the API and worker together and check that the old link is refused. Request a new link and verify success. Keep the normal development key unchanged unless intentionally testing rotation.
