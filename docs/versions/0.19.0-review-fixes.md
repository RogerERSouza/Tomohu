# Tomohu 0.19.0 — Corrections after branch review

Date: 2026-11-09. Patch baseline: `ddbbc58de8807eeb8eb8dd08da24bf817bb454de` on `refactor/v0.19.0-frontend`.

## Scope

The review reproduced four pre-existing defects on both main and the 0.19 branch. This patch fixes them within the unmerged 0.19 release; it does not introduce a new feature or undertake the next architectural refactor. Backend code, dependencies, notebook schema version and storage keys are unchanged.

| Defect                                                                     | Correction                                                                                               |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Recovery import cleared the warning but left autosave blocked              | Track the current save block and clear it only after a successful explicit replacement                   |
| All-day reminders supplied empty legacy times to timed-event editing       | Derive valid defaults through a pure helper; retain valid explicit, legacy and midnight times            |
| Invalid counter timestamps passed import validation and crashed the editor | Require a parseable, in-range timestamp before accepting the backup; format invalid runtime dates safely |
| Mobile section tags extended beyond the modal                              | Constrain intrinsic field/row width and let the input shrink while keeping the action visible            |

The reminder time initializer lives in `features/reminders/reminderFormTimes.ts`, separate from React markup. No input data is silently repaired during backup import.

## Compatibility and data preservation

- Valid existing notebooks and backups keep schema version 1 and their current keys. Valid counter timestamps, including existing ISO values with or without milliseconds and offsets, remain accepted unchanged.
- Backups containing unparseable/out-of-range counter timestamps are rejected before the replacement confirmation. They do not overwrite the active notebook.
- If such data already exists in browser storage, the existing preservation policy pauses autosave and retains the stored bytes. It does not delete or automatically rewrite them.
- A failed recovery write leaves saving blocked. Once a valid, explicitly confirmed replacement is written successfully, later edits autosave and survive reload.
- Existing UI copy and design are preserved apart from making the clipped tag action visible. Date formatting now has a controlled `Data inválida` fallback instead of throwing.

## Run on Windows

From the repository root after applying the corrective patch:

```powershell
npm.cmd run lint
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd run typecheck
npm.cmd run test:e2e
```

The prior patch already installed all required dependencies and Chromium; no new dependency was added here. If this is a fresh checkout, run `npm.cmd ci` and `npx.cmd playwright install chromium` first. Browser tests build and start an isolated production preview on port 4173; Docker and Uvicorn are not required.

For a quick manual UI check with `npm.cmd run dev`, edit a future all-day reminder, select `Um horário` or `Com duração`, save and reopen it. A valid time must remain visible. In a narrow viewport, open new/edit section and add a tag; the entire `Adicionar` action must stay inside the dialog. Recovery and malformed-file tests use isolated browser contexts so personal browser data does not need to be corrupted manually.
