# 0.22.0 — Private sections and content

Baseline: `a8912f7` on main. New branch: `feature/v0.22.0-private-sections`.

## Behavior

- Configure one privacy password in Settings after verifying the account email. It can equal the login password, but both credentials change independently.
- Open a synchronized account section/content and choose the privacy action. Protecting a section also moves its descendants and content. The server removes the data from the public snapshot atomically.
- Settings support generic locked cards at their original parent location or a dedicated private area. Deleted/private parents do not make the private aggregate unreachable: use the dedicated area.
- Unlock with the privacy password for up to five minutes in the current authenticated tab. Private edits stay in memory until an automatic revision-checked save completes. Locking hides the editor; unlock again in the same workspace to resume the retained draft. Reloading closes memory-only drafts.
- Recover through the verified account email using a distinct single-use link. This preserves private data and the account login password.
- Export private JSON explicitly from the unlocked editor. Public backups do not contain private aggregates. Private JSON exports are readable without a password. Older public copies cannot be recalled.

Protection is server-enforced access control, not end-to-end encryption. See ADR 0005 for the security boundary and database backup requirements.

## Windows validation guide

Run each block separately and stop if it fails. Use the new project path without OneDrive. Keep Docker Desktop open. Keep manually launched API/frontend/mail worker processes closed during live integration tests.

### 1. Apply the patch on a clean main

```powershell
Set-Location 'C:\Users\Roger\Documents\VsCode\Tomohu'
git status --short
git switch main
git pull --ff-only
git switch -c feature/v0.22.0-private-sections
git apply --check .\tomohu-v0.22.0-private-sections-a8912f7.patch
git apply .\tomohu-v0.22.0-private-sections-a8912f7.patch
npm.cmd ci
.\backend\.venv\Scripts\python.exe -m pip install -e ".\backend[dev]"
```

No `.env` values change. Keep the existing stable JWT secret shared by the API and worker.

### 2. Backend regression checks against the dedicated test database

```powershell
docker compose -f .\backend\docker-compose.yml up -d
Push-Location backend
try {
    .\.venv\Scripts\python.exe -m ruff check .

    Remove-Item Env:TOMOHU_TEST_DATABASE_URL -ErrorAction SilentlyContinue

```

### 5. Back up the development database and migrate

Review the backup destination and keep backups private. These commands create a dump inside the container and copy it as binary without PowerShell text redirection.

```powershell
docker compose -f .\backend\docker-compose.yml exec -T postgres pg_dump -U tomohu -Fc -f /tmp/tomohu-before-022.dump tomohu
docker compose -f .\backend\docker-compose.yml cp postgres:/tmp/tomohu-before-022.dump .\tomohu-before-022.dump
Push-Location backend
try { .\.venv\Scripts\python.exe -m alembic upgrade head } finally { Pop-Location }
```

The migration adds columns/table and does not rewrite existing public snapshots. Do not manually downgrade a database containing privacy data.

### 6. Manual use

Start API, frontend and email worker using the existing setup instructions. Verify the account email, configure privacy in Settings, open a synchronized account notebook and use its creation form or three-dot menu to mark a section/content private, then enter the privacy password. Confirm both display modes, wrong-password handling, automatic private saves, leaving/reopening an item, email recovery, public restoration, and public/explicit-private backups.

## Release checks

Do not merge until local checks and GitHub CI pass. Never commit `.env`, `.outbox`, database dumps, `.patch` files, or browser test artifacts. No deployment, account reset or database migration is performed by merely applying this patch.
