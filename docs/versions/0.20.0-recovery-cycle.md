# 0.20.0 local recovery and API contract correction

Baseline: `feature/v0.20.0-accounts-sync`, commit `40accc6aa7bea90744f49b0113075911c048e6bb`.

## Result

Guest notebooks now detect another tab's writes and clear events, compare the stored checkpoint before autosave, pause on a mismatch and retain an exportable open draft. The other tab's durable snapshot stays in `task.notebook.v1`. Confirmed replacement preserves displaced raw data under a guest recovery key before writing; failure leaves the current notebook intact. Export the open copy before reloading to view the other tab's saved version.

Valid account-cache exports are ordinary notebook backups. Older workspace-envelope files are also accepted after validating both snapshots and all required metadata. Storage and imports use one React-independent codec rather than separate integrity rules. Damaged cache bytes remain available as a raw file and never bypass snapshot validation.

API counter timestamps and legacy reminder dates normalize Python-only ISO variants into browser-readable forms. Existing stored snapshots normalize in the response without a database rewrite. Already-supported ISO strings keep their wall-time/offset semantics; unsupported offset-second forms convert to UTC. Calendar overflow returns 422. No migration, dependency package or password-policy change is included.

## Automatic review cycle

1. Reproduced the original guest overwrite, recovery-file import failure and unreadable API date cases from baseline `40accc6`.
2. Implemented the protections and permanent regressions, including desktop/mobile export followed by actual import and a real second guest tab.
3. Reviewed failure paths. A stale queued autosave status could clear the new conflict warning; the status callback now respects the pause. The import dialog now displays replacement errors, and timestamp normalization overflow becomes a validation failure. A later offset review also found Python-normalized minute overflow; these offsets now canonicalize before reaching the browser.
4. Repeated focused checks and the required suites. A separate 25-input API review corpus produced 18 accepted snapshots; all 18 passed frontend validation. Rejected inputs returned validation responses rather than internal server errors. An additional offset corpus produced 176 normalized strings, all parseable by JavaScript.

The reviewed/reproduced issues have no outstanding failing regression. This is bounded verification, not a proof that every possible browser, concurrency or data defect is absent. Guest recovery records are local browser data; export important copies before clearing site data.

## Apply and test on Windows

From the repository root on the existing 0.20 feature branch, with previous work committed:

```powershell
git status --short
git branch --show-current
git apply --check .\tomohu-v0.20.0-recovery-cycle-40accc6.patch
git apply .\tomohu-v0.20.0-recovery-cycle-40accc6.patch
npm.cmd run lint
npm.cmd run format:check
npm.cmd test
npm.cmd run build
npm.cmd run typecheck
npm.cmd run test:e2e
```

Keep the Docker PostgreSQL service running. Check the backend using the dedicated test database:

```powershell
Push-Location backend
try {
    docker compose up -d
    .\.venv\Scripts\python.exe -m ruff check .
    .\.venv\Scripts\python.exe -m ruff format --check .
    $env:TOMOHU_TEST_DATABASE_URL = 'postgresql+psycopg://tomohu:tomohu@localhost:5432/tomohu_test'
    .\.venv\Scripts\python.exe -m pytest
} finally {
    Remove-Item Env:TOMOHU_TEST_DATABASE_URL -ErrorAction SilentlyContinue
    Pop-Location
}
```

Stop the ordinary development API before the live runner, which needs port 8000. The runner starts and stops its isolated API:

```powershell
$env:TOMOHU_E2E_DATABASE_URL = 'postgresql+psycopg://tomohu:tomohu@localhost:5432/tomohu_test'
try {
    .\backend\.venv\Scripts\python.exe scripts\run_live_e2e.py
} finally {
    Remove-Item Env:TOMOHU_E2E_DATABASE_URL -ErrorAction SilentlyContinue
}
git --no-pager diff --check
```
