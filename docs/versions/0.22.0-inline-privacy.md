# 0.22.0: Per-item privacy interaction reformulation

Apply this incremental patch **after the original v0.22.0 private-sections patch**, on `feature/v0.22.0-private-sections`. Do not reapply the original patch or restore the database backup. The previous migration remains intact.

## Behavior

- Set the independent privacy password in Settings after verifying the account email.
- Creation forms and each section/content settings menu have a privacy checkbox. New private items go directly to the account's private storage, without an intermediate public copy.
- The default keeps locked cards among their siblings. Clicking one requests the privacy password in a compact dialog and opens the normal section/content screen. Leaving the item saves pending edits and locks it.
- Private edits save automatically. A private section protects its descendants together; descendant controls show inherited protection. Removing privacy from the protected root restores it publicly.
- The optional private list is selected in Settings. It gathers protected roots, then opens the same normal screens. It is not a second editor.
- Saving errors/conflicts retain the in-memory draft and block navigation that would discard it. Export the draft before replacing it with the remote version or leaving without saving. Reloading the browser can lose an unsaved memory-only draft.
- Private exports are readable JSON. Public backups contain public data only. Existing public copies/backups cannot be recalled; this is server access control, not end-to-end encryption.

The obsolete `PrivateWorkspace` editor and its manual save/lock controls were removed. Public notebook data format, account login and privacy password recovery remain compatible. No new dependencies or environment keys are needed.

## Back up, then migrate development

```powershell
docker compose -f .\backend\docker-compose.yml exec -T postgres pg_dump -U tomohu -Fc -f /tmp/tomohu-before-inline.dump tomohu
if ($LASTEXITCODE -ne 0) { throw 'Backup failed.' }
docker compose -f .\backend\docker-compose.yml cp postgres:/tmp/tomohu-before-inline.dump .\tomohu-before-inline.dump
if ($LASTEXITCODE -ne 0) { throw 'Backup copy failed.' }
Push-Location backend
try {
    .\.venv\Scripts\python.exe -m alembic upgrade head
} finally {
    Pop-Location
}
```

Migration `20261112_05` only adds an item-position column. Existing private snapshots/passwords remain intact. Items protected before the update use position zero because their exact previous sibling position was not stored.
